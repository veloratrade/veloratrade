## 1. Implementation

**Single authoritative frontend presentation map** (`admin/index.html` K-map + `velora-admin-ai.js`):

```js
// enum -> K-stem  (template map resolves stem -> full catalog key -> localized text)
var STATUS_MAP = {
  VALID:'aiStatus.valid', SUCCESS:'aiStatus.success', UNVERIFIED:'aiStatus.unverified',
  NOT_CONFIGURED:'aiStatus.notConfigured', INVALID_CREDENTIAL:'aiStatus.invalidCredential',
  AUTH_FAILED:'aiStatus.authFailed', EXPIRED:'aiStatus.expired', REVOKED:'aiStatus.revoked',
  DISABLED:'aiStatus.disabled', INSUFFICIENT_PERMISSION:'aiStatus.insufficientPermission',
  QUOTA_EXCEEDED:'aiStatus.quotaExceeded', RATE_LIMITED:'aiStatus.rateLimited',
  REGION_RESTRICTED:'aiStatus.regionRestricted',
  PROVIDER_UNAVAILABLE:'aiStatus.providerUnavailable',
  SERVICE_UNAVAILABLE:'aiStatus.serviceUnavailable', UNKNOWN:'aiStatus.unknown',
  NETWORK_ERROR:'aiStatus.networkError', TIMEOUT:'aiStatus.timeout', PROVIDER_ERROR:'aiStatus.providerError'
};
var STATUS_CLS = {
  VALID:'velora-st-ok', SUCCESS:'velora-st-ok',
  UNVERIFIED:'velora-st-muted', NOT_CONFIGURED:'velora-st-muted',
  INVALID_CREDENTIAL:'velora-st-err', AUTH_FAILED:'velora-st-err',
  EXPIRED:'velora-st-err', REVOKED:'velora-st-err', DISABLED:'velora-st-err',
  INSUFFICIENT_PERMISSION:'velora-st-warn', QUOTA_EXCEEDED:'velora-st-warn',
  RATE_LIMITED:'velora-st-warn', REGION_RESTRICTED:'velora-st-warn',
  PROVIDER_UNAVAILABLE:'velora-st-unavail', SERVICE_UNAVAILABLE:'velora-st-unavail',
  UNKNOWN:'velora-st-unavail',
  NETWORK_ERROR:'velora-st-err', TIMEOUT:'velora-st-err', PROVIDER_ERROR:'velora-st-err'
};
function statusMeta(s){ return STATUS_MAP[s] ? [STATUS_MAP[s], STATUS_CLS[s]||'velora-st-muted'] : null; }
function statusLabel(s){ /* resolves K(stem) -> VeloraLocale.t(key); unmapped -> raw enum fallback */ }
```

- **Machine state preserved:** the backend enum (`vc.status`) is kept verbatim in a muted
  **technical line** (`admin.ai.statusDetail` + raw enum). The colored badge shows only the
  *localized label* — the enum is never destroyed or replaced.
- **Semantic classes (not one generic red "Error"):** `velora-st-ok` (success) / `velora-st-warn`
  (rate/quota/permission/region) / `velora-st-err` (credential/auth/expired/revoked/disabled/network/
  timeout/provider) / `velora-st-unavail` (provider/service unavailable, unknown) / `velora-st-muted`
  (not-configured / unverified). Distinct neutral/success/warning/error/unavailable semantics.
- **CSS:** injected once via JS (`#velora-admin-status-css`) — a clean `velora-st` taxonomy +
  `overflow-wrap:anywhere` + `max-width:100%` so a long status wraps instead of overflowing. No
  arbitrary new colors; contrast is sufficient (light-on-dark, bordered pills).
- **Test Connection UX:** a per-provider busy guard (`providerBusy`) prevents duplicate submissions;
  the button is disabled and set to a localized "Testing…" during the call, then restored. Results
  always re-fetch authoritative state (never client-authored success).
- **Integrations panel delegates** to the same `VeloraStatus` mapper (single source), with a guarded
  fallback to the prior `admin.integrations.result.*` keys if the mapper is absent. A per-card
  `role="status"` / `aria-live="polite"` badge renders the localized classification.

### Canonical localization mechanism (reused, no second system)
- `K(stem)` via `window.VeloraAdminAIKeys` in `admin/index.html` (template = single source of key
  literals) → `VeloraLocale.t(key)` from the feature chunk. 19 `aiStatus.*` stems + `statusDetail`
  were added to the template K-map; master `en`/`fa` catalogs carry the `admin.ai.status.*` text and
  the admin feature chunk was regenerated by `build_localized_static.py`.
