DATETIME EVIDENCE RULES (critical):
- rawOpenText/rawCloseText are the SOURCE OF TRUTH for what the screenshot shows. Copy the date/time text EXACTLY as it appears: keep the same digits (Persian ۰۱۲… or Arabic-Indic ٠١٢… or Latin), the same separators (/ - .), the same component order, the same clock. Do NOT convert digits, do NOT reorder, do NOT add seconds, do NOT add a timezone, offset, or "Z".
- openTime/closeTime are only a best-effort Gregorian machine-readable reading (e.g. "2026-08-31 14:30"). NEVER append "Z", a UTC marker, or an offset to them. If the on-screen value is Jalali (Persian date such as ۱۴۰۵/۰۶/۰۹), you MAY still provide rawOpenText verbatim; set openTime to null unless a Gregorian value is also visible — do NOT convert the calendar yourself.
- sourceCalendar reports the calendar the visible date is rendered in. A date like "31/08/2026" or "2026-08-31" is gregorian; a date like "۱۴۰۵/۰۶/۰۹" is jalali. Use "unknown" if you cannot tell.
- The UI/interface language (Persian or English) is NOT evidence of the date's calendar. A Persian-language screen can still show a Gregorian date. Read the DATE itself.
- dateFormat reports the visible ordering. If day vs month cannot be distinguished reliably (e.g. "03/04/2026" where both are <= 12), return "unknown" — never guess which is the month.
- timezoneText: only a timezone label or UTC offset that is literally printed on screen (e.g. "GMT+2", "UTC+3:30", "EST", "server time (UTC+0)"). Copy it verbatim; do not map abbreviations to a city and do not complete a partial value.
- timezoneOffsetHintMinutes: only if an explicit numeric UTC offset is clearly shown (e.g. "UTC+3:30" -> 210, "GMT-5" -> -300). Otherwise null.
- NEVER infer the timezone from: the interface language, the broker/platform name (MetaTrader, MT5, OANDA, …), the symbol, a bare clock like 14:30, a date like 31/08/2026, your model knowledge of the broker, the user's likely location, the current date, or market/trading-session conventions.
- NEVER output a trading session (Asia/London/New York/Late/overlap) or classify one.
- Do not convert Gregorian to Jalali or Jalali to Gregorian. Do not compute UTC. Backend code does all normalization.

GENERAL RULES:
